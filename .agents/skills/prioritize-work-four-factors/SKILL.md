# เลือกงานที่ควรปรับปรุงก่อน

ใช้ **เงิน + เวลา + ผลกระทบ + ความถี่** ด้านละ 0–3 น้ำหนักเท่ากัน รวม 0–12 เพื่อเลือกงานไปตรวจและปรับปรุง ไม่ใช่คำสั่งให้ทำ automation ทันที

## วิธีใช้กับ Phou หรือทีม

1. ใช้ข้อมูลที่มี ระบุธุรกิจเดียวและช่วงประเมินเดียว เริ่มจากงานที่ผู้ใช้ให้ ไม่ค้นข้อมูลบริษัทอื่นเพื่อเติมตาราง ถ้ายังขาดให้ถามเฉพาะช่องที่มีผลต่อคะแนน
2. ให้ผู้ใช้เปิด [เครื่องคำนวณภาษาไทย](assets/calculator.html) ใน browser ได้ทันทีโดยไม่ใช้ server หรืออินเทอร์เน็ต หรือใช้ [ตารางพร้อมตัวอย่างและช่องว่าง](assets/TABLE_TH.md) ให้เล่างานสั้น ๆ แล้วช่วยกรอก 4 ช่อง: ค่าใช้จ่ายตรงต่อครั้ง (LAK ไม่รวมแรงงาน), นาทีคนรวมต่อครั้ง (รวมทุกคน ตรวจและแก้), ผลเมื่องานช้าหรือผิดพร้อมเหตุผลจริง, ครั้งต่อเดือน รายละเอียดค่าใช้จ่ายและแหล่งข้อมูลเติมได้ในช่องย่อยแบบเลือกใช้ หน้าเครื่องคำนวณเริ่มว่าง ตัวอย่างมีป้ายสมมติ บันทึก JSON ก่อนปิดเพื่อเก็บข้อมูลไว้
3. ให้คะแนนตาม [เกณฑ์และรูปแบบข้อมูล](references/MODEL_TH.md) ใช้ `scripts/score.py` คำนวณซ้ำได้ ไม่ต้องให้ผู้ใช้กรอก JSON เอง แปลงคำตอบหรือตารางเป็น JSON ให้ โดยไม่เดาค่าที่ขาด
4. ส่งตารางสั้น: อันดับ งาน เงิน เวลา ผลกระทบ ความถี่ รวม/12 และสิ่งที่ควรตรวจต่อ เรียงรวมมากก่อน ตามด้วยผลกระทบมากก่อน หากยังเท่ากันเลือกที่แก้ง่ายกว่าเฉพาะมีหลักฐานเปรียบเทียบได้ มิฉะนั้นอันดับร่วม
5. ก่อนเสนอทดลองงานที่เลือก เช็กสั้น ๆ: ลดต้นทุน/นาทีคนส่วนไหนได้จริง, ตรวจวิธีทำและเครื่องมือแล้วหรือยัง, ติดระบบหรือคนอนุมัติอะไร ใช้คำตอบเป็นความพร้อม ไม่บวก Confidence/Ease เข้า 4 ปัจจัย เสนอขั้นทดลองและวิธีวัดผลตามข้อมูลที่มี ไม่ขยายเป็นแบบสอบถาม audit ยาว

## กติกาที่เปลี่ยนไม่ได้โดยเงียบ ๆ

- เกณฑ์เริ่มต้นเป็น heuristic ที่ Phou อนุมัติให้เริ่มใช้ ยังไม่ผ่านการปรับเทียบกับผลจริง เปลี่ยนเกณฑ์ได้เมื่อระบุเหตุผล และใช้ชุดเดียวตลอดการเปรียบเทียบ
- ไม่ทราบ ≠ 0: ช่องว่าง/null/`?` แสดง “ข้อมูลไม่ครบ” คะแนนรวม/อันดับเป็น `?`; ค่าติดลบ, NaN/Infinity, หมวดผลกระทบผิด หรือสกุลเงินไม่ตรงต้องแก้ก่อน
- ไม่คิดค่าแรงซ้ำในเงิน และไม่คูณความถี่เข้าค่าเงิน/เวลาก่อนให้คะแนน ความถี่ถูกนับแยกเพียงครั้งเดียว
- รายปีหาร 12; รายวันคูณวันทำงานจริงของงานนั้นต่อเดือน ห้ามสมมติ 30 วัน รองรับเศษครั้งต่อเดือน
- งาน 0 ครั้งแสดง “ไม่เกิดในช่วงประเมิน” และไม่มีอันดับในงานปัจจุบัน แม้ภาระต่อครั้งสูง
- ผลกระทบใช้เหตุผลจริง ไม่เดาจากชื่องาน; หากแหล่งเป็นคำบอกหรือประมาณให้ระบุ ไม่เรียกว่าได้รับการยืนยันแล้ว
- คะแนนสูงไม่พิสูจน์เงินที่ประหยัดได้ และยังไม่ใช่อำนาจอนุมัติแก้ระบบ เผยแพร่ ส่งข้อความ หรือใช้เงิน

## เรียกตัวคำนวณ

ต้องมี Python 3.10+ ใช้เฉพาะ standard library; รันจากโฟลเดอร์สกิลที่แตกไฟล์แล้ว:

```text
python scripts/score.py assets/example.json --format markdown
python scripts/score.py input.json --format json --output result.json
python -m unittest discover -s scripts -p "test_*.py" -v
```

`--output` ไม่ทับไฟล์เดิม ใช้ชื่อใหม่; exit 0 = ข้อมูลถูกต้องครบ (รวมงานไม่เกิด), 1 = มีข้อมูลขาด, 2 = มีข้อมูลผิด/อ่านไม่ได้ รายละเอียดอยู่ในผลลัพธ์

สำหรับที่มา ICE และขอบเขตการประยุกต์ อ่าน [แหล่งอ้างอิงที่พกไปกับสกิล](references/SOURCES_TH.md) เมื่อต้องอธิบายที่มา ไม่ต้องโหลดแบบสอบถาม ICE เดิมเพื่อใช้งานตารางนี้

## เครื่องคำนวณออฟไลน์และการตรวจ

หน้า HTML รองรับเพิ่ม/แก้/ลบแถว แสดงคะแนน อันดับ ข้อมูลขาด/ผิด ปรับเกณฑ์ทั้งชุดพร้อมเหตุผล และบันทึก/เปิด JSON รูปแบบเดียวกับ Python อ่าน [การใช้เครื่องคำนวณ](references/data-format.md) เมื่อต้องแปลงหน่วยหรือพัฒนาต่อ

`scripts/score.cjs` เป็น engine ฝั่ง browser; `node scripts/build.cjs` ฝัง engine ลง HTML ไฟล์เดียว ไม่ต้องใช้ Node/Python เพื่อเปิดหน้า ผู้ดูแลรัน `node scripts/test-score.cjs` และ Python unittest หลังเปลี่ยนสูตร ดู [ผลตรวจ](references/verification.md) เพื่อทราบขอบเขตที่ทดสอบจริง
