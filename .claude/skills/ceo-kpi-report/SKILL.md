# KPI reporting

Read [the shared local runtime contract](../bni-second-brain/references/codex-runtime.md) before work.
Reuse `data/state.json` and the selected company's accessible files; save outputs under `work/ceo/`.

Read the selected KPI definitions and actual data. For each metric retain formula, numerator/denominator,
unit, period, source locator, target source and freshness. Unknown target is not zero and cannot receive a red/green status.
Compare like periods and currencies only; explain partial-period coverage. Rate movement uses percentage points where appropriate.
Distinguish tasks completed from outcomes achieved. Decompose movement only when driver data supports it; label causes as hypotheses.
Reconcile any variance bridge back to beginning plus drivers equals ending; disclose residuals rather than forcing an explanation.
Deliver one concise KPI readout with actual vs comparable baseline, data limits, likely drivers and an evidence-gathering next step.
Reuse the existing read-team-performance method where relevant without inventing staff performance or accessing unrelated records.
Selective inspiration: Anthropic variance-analysis, pinned in docs/CEO_SOURCES.json; no warehouse or email connector required.
