# Four-workshop preview: observed checks

Date: 8 October 2026, Asia/Vientiane. Version: 4.1.0-four-workshops-preview.
Status: local implementation preview. Recipient ChatGPT Plus acceptance is not yet verified.
The current scope replaces the earlier six-segment course with four workshops. Older results
and the [previous test report](TEST_REPORT_2026-10-07.md) retain their historical meaning.

## What changed

- One installation URL, onboarding choices before questions, saved-answer reuse and an explicit browser-only starter.
- WS1 reads/reconciles business data before a supported recommendation; WS2 prepares bounded Apify research or labelled exports; WS3 creates a testable Winning Zone; WS4 builds public-safe static site files for Netlify Drop.
- Core workshops use one assistant on Plus. Optional native team execution is never inferred from files or replaced by simulated independent agents.
- Desk exposes next action, done criterion, evidence, blocker, project and priority; reads saved results; local adapter supports up to 2000 tasks. Original standalone HTML is preserved and supports 50.
- Versioned new results preserve displaced entries in result_history. Old WS2/3/4 meanings remain legacy.
- Removed unsupported learning-after-N-runs claims, mandatory connection prerequisites and conflicting decision-store instructions from optional utilities.

## Independent review found and fixed

1. A task with existing evidence but no criterion could fail when marked Done. Transitions to
   Done now record user_reported regardless of old evidence; completion-field edits invalidate
   earlier review, while unchanged reviewed completion is preserved. Regressions pass.
2. Native exports contained optional result IDs and task fields unsupported by original HTML.
   A separate desk-data-standalone export now omits those features with explicit warnings and
   rejects oversized tasks/text/calendar metadata without truncation. The actual original HTML
   validator is exercised in a regression. It is a limited copy, not a full backup.
3. The shell-only installer receipt hardcoded the old version. It now reads the verified
   manifest version. The public build and installation guide use 4.1.0-four-workshops-preview.
4. Visual inspection found a missing space where a mobile line break was hidden in the
   synthetic website. This was sent to the site author for repair; inspect the accompanying
   final rehearsal QA for the resolution before using that demo.

## Reproduce and inspect

Run `node scripts/verify-ceo.mjs`, `node --test tests/ceo-state.test.mjs tests/ceo-cli.test.mjs`,
`node tests/workshop-contracts.mjs`, `node tests/four-workshop-fixture-check.mjs`,
`node tests/audit-skill-links.mjs`, and `python -m unittest discover -s tests -v`.
Browser checks use `node tests/desk-browser.cjs` with an available Playwright module in
CEO_PLAYWRIGHT and Chrome via CEO_BROWSER_CHANNEL. See [Desk evidence](evidence/desk-browser-2026-10-08.json)
and [Desk audit](DESK_AUDIT_2026-10-08.md). Python/Git/Playwright are maintainer tools.

The builder validates mirrors, original-skill retention, native names, blank scaffold,
paths, member hashes and deterministic ZIP bytes. It excludes personal data and reads only
tracked public sources plus the frozen learner scaffold. Final ZIP hashes and installation
receipts are generated after the build; a self-contained ZIP cannot contain its own hash.
The matching manifest/receipt, not a stale filename or old report, identifies the received build.

of this local revision. Online links serve the last published version until publication is
separately authorized; use a matching local archive to review an unpublished preview.
